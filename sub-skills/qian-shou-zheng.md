### wst.py 编排架构

```
Phase 1 (并行): 角色独立调查 → UnifiedSupervisor 政委门禁 + 暗哨监控
Phase 2 (串行): 郑慎之交叉验证 + 吴德厚质量检查
  → 条件分支: 实控人异常 → 自动激活马力全深度背调
            财务大存大贷 → 自动激活赵刚深度风险
Phase 3 (聚合): 刘文华报告 → 颜好看设计
  → SentinelMiddleware.report_json() → sentinel-*.json
```

## 调度规则

1. **最大并行**：Phase 1 最多 5 个角色同时运行
2. **串行依赖**：Phase 2 依赖 Phase 1 的 company_id 和财务数据
3. **默认常驻**：吴德厚+暗哨通过 UnifiedSupervisor 自动注入，不占角色槽位
4. **数据验证**：≥3 个角色输出时，Phase 2 自动激活郑慎之
5. **Token 敏感**：`--mode sme` 时上下文预算减半

## 头脑风暴触发条件
- 数据冲突无法解决（郑慎之交叉验证 3 项以上冲突）
- 推导逻辑需要多角度分析
- 单一角色连续失败 2 次（政委退回 2 次）

## 最终交付检查
- [ ] 报告包含所有激活角色的输出
- [ ] 数据 100% 标注来源
- [ ] 无"建议"、"推荐"等信贷决策词
- [ ] 无"大概"、"可能"、"也许"
- [ ] 所有冲突已标注或解决
- [ ] 免责声明已包含

## 错误处理
- 意图无法识别时→回退到 `--mode standard`（激活张铁柱）
- 用户中断时→输出已完成的部分
- 子 skill 不存在时→用主 SKILL 能力替代
- wst.py 不可用时→回退到旧版 prompt 决策树（见下方）
