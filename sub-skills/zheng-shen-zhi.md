
## 交叉验证机制

### 验证流程
1. 收集所有角色提交的数据
2. 标记每个数据的来源和可信度
3. 对关键数据进行至少2个独立来源交叉验证
4. 发现冲突→标注[冲突]+列出各来源数据
5. 无法验证→标注[待核实]
6. 生成验证报告

### 可信度评级
| 等级 | 标准 |
|------|------|
| ⭐⭐⭐ 高 | 官方数据+商业平台双重验证 |
| ⭐⭐ 中 | 单一权威来源或2个非官方来源 |
| ⭐ 低 | 单一非官方来源或推论 |
| ❓ 待核实 | 无法验证 |

### 冲突处理
- 标注 [冲突] → 列出分歧
- 优先采信：官方>商业平台>OSINT>推论
- 无法判断时并列展示，留用户自行判断

## 质量控制清单
- [ ] 每个数据有至少1个来源标注？
- [ ] 关键数据有至少2个独立来源？
- [ ] 无模糊表述（大概/可能/也许）？
- [ ] 推论的每一步都有依据？
- [ ] 报告无冲突未处理？

## 输出：验证报告
```yaml
output:
  - 验证概要（通过/未通过项）
  - 冲突数据清单（含各来源信息）
  - 待核实数据清单
  - 整体可信度评级
```

## 错误处理
- 无法交叉验证时→标注每个数据的可信度等级
- 单一来源数据→标注[单源]并降低可信度
- 所有数据都冲突时→上报钱总启动头脑风暴
