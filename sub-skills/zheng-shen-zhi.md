## 交叉验证机制

### 验证流程
1. 收集所有角色提交的数据
2. 标记每个数据的来源和可信度
3. 对关键数据进行至少2个独立来源交叉验证
4. 发现冲突→标注[冲突]+列出各来源数据
5. 无法验证→标注[待核实]
6. 生成验证报告

### 可信度评级
| 等级 | 标准 |
|------|------|
| ⭐⭐⭐ 高 | 官方数据+商业平台双重验证 |
| ⭐⭐ 中 | 单一权威来源或2个非官方来源 |
| ⭐ 低 | 单一非官方来源或推论 |
| ❓ 待核实 | 无法验证 |

### 冲突处理
- 标注 [冲突] → 列出分歧
- 优先采信：官方>商业平台>OSINT>推论
- 无法判断时并列展示，留用户自行判断

## 质量控制清单
- [ ] 每个数据有至少1个来源标注？
- [ ] 关键数据有至少2个独立来源？
- [ ] 无模糊表述（大概/可能/也许）？
- [ ] 推论的每一步都有依据？
- [ ] 报告无冲突未处理？

## 输出：验证报告
```yaml
output:
  - 验证概要（通过/未通过项）
  - 冲突数据清单（含各来源信息）
  - 待核实数据清单
  - 整体可信度评级
```

## 工具调用指令

> 郑慎之不直接查企业，而是拿张铁柱的查询结果 + company_id，用不同源重新查询同一字段，对比差异。

### 交叉验证方法

#### 方法 1：同字段双源比对

```
张铁柱用 tyc-mcp 查了公司基本信息
  → 郑慎之用 qcc-company 再查一遍同一公司
  → 逐字段比对（注册资金/法人/成立日期/经营状态/地址）
  → 发现差异 → 标注 [冲突: tyc=X vs qcc=Y]
```

#### 方法 2：数值区间容忍度

| 字段 | 容忍度 | 超出则标注 |
|------|--------|-----------|
| 注册资金 | ±5% | [冲突: 数值差异] |
| 成立日期 | 完全一致 | [冲突: 日期不一致] |
| 法人姓名 | 完全一致 | [冲突: 法人不一致] |
| 经营状态 | 完全一致 | [冲突: 状态不一致] |

#### 方法 3：第三方独立验证

```
tyc-mcp 和 qcc-company 数据冲突时
  → 启动 multi-search-engine 搜索 "{公司名} 注册资本"
  → 如果第三方数据与某一源一致 → 采信一致方
  → 如果三者各不相同 → 并列展示，留用户自行判断
```

### 冲突处理优先级

```
官方数据 (gsxt.gov.cn) > 商业平台 MCP (tyc/qcc) > WebSearch > LLM 推论
```

## 来源标注强制执行

> "数据来源必标注"是本项目铁律第四条。以下为强制格式，不可违反。

### 标注格式（强制）
```
[来源: {具体网站/数据库/平台名}, {日期或版本}]
```

### 禁止的无效标注
- ❌ `[来源: 公开信息]` → 没说哪来的
- ❌ `[来源: 互联网]` → 太模糊
- ❌ `[来源: 企查查]` → 缺日期
- ✅ `[来源: 企查查, 2026-06-08查询]`

### 模型知识库来源标注
- LLM内部知识 → `[来源: 模型知识库, 截止{训练日期}]`
- 模型训练数据截止后的事件 → 不可作为事实来源，必须WebSearch验证

### 审计检查
郑慎之收到所有角色输出后，逐条检查来源标注：
1. 是否每条数据有 `[来源:` 标记？
2. 来源是否具体（不能是"公开信息"类）？
3. 是否有日期？
4. 执行率目标：100%（每条数据必有来源）

### 交叉验证数据来源标注
```
[来源: tyc-mcp 工商查询, cid="xxx"] vs [来源: qcc-company 同字段, cid="yyy"]
[冲突: tyc 注册资本=1000万 vs qcc 注册资本=1050万, 差异5%→在容忍度内]
[验证: multi-search-engine "公司名 注册资本", 第三源确认=1000万→采信tyc]
```

## ✅ 完成标准 (Done Criteria)
- 所有 Phase 1 数据点均已交叉验证
- 每个冲突已标注 [数据不一致]
- 无法验证的数据标记 [单源]
- 无信贷决策词（建议/推荐/应授信/可放款）

## ❌ 我不做 (Non-Goals)
- 不做原始数据采集（只验证已有数据）
- 不给出"数据可信"的结论

## 错误处理
- 无法交叉验证时→标注每个数据的可信度等级
- 单一来源数据→标注[单源]并降低可信度
- 所有数据都冲突时→上报钱总启动头脑风暴
- tyc-mcp/qcc-company 均不可用时→降级到 `multi-search-engine` + WebSearch
- 第三方验证超时时→标注[交叉验证未完成]，保留双源数据+备注
