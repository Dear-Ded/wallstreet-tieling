## 一B、身份解析引擎：多向量交叉锁定

> **核心问题**：如何确定"微博的张三"和"领英的Zhang San"是同一个人？

### 身份指纹（Identity Fingerprint）

一个人的数字身份由多个向量组成，单一向量匹配不可靠，多向量交叉锁定精准度 > 95%。

| 身份向量 | 唯一性 | 稳定性 | 获取难度 | 验证方式 |

### 交叉锁定公式

```
身份置信度 = Σ(匹配向量权重 × 匹配度) / Σ(所有向量权重)

匹配度: 完全匹配=1.0, 高度相似=0.7, 可能匹配=0.4, 不匹配=0

判定: ≥0.85 → 确认同一人, 0.6-0.85 → 高度疑似, <0.6 → 不足以下结论
```

### 多向量交叉验证实战流程

```
Step 1: 收集种子信息 → 姓名+公司+城市 (置信度30%)
Step 2: 企查查/天眼查 → 确认法定代表人/股东身份 (置信度+25% → 55%)
Step 3: 裁判文书网 → 确认身份证号前段+户籍 (置信度+15% → 70%)
Step 4: Maigret → 用户名跨平台匹配 → 发现微博/知乎 (置信度+10% → 80%)
Step 5: 微博内容 ↔ 知乎内容交叉 → 相同话题/时间线吻合 (置信度+10% → 90%)
Step 6: 微博头像 → PimEyes → 领英头像匹配 → 确认职业履历 (置信度+5% → 95%)
→ 结论: 95%置信度确认为同一人
```

## 一C、密码行为分析与撞库（借鉴 CUPP/Hashcat/CeWL/SET）

> 免责声明：以下技术用于密码行为分析和安全评估。使用者应自行判断合规性。

### 密码行为画像（借鉴 CUPP - Common User Passwords Profiler）

**核心原理**：大多数人的密码遵循可预测的模式——基于个人信息（生日、姓名、手机号、宠物名）加上固定模式（加!@#等特殊字符、首字母大写、年份后缀）。CUPP 通过收集目标的个人信息自动生成高命中率的密码字典。

**个人信息 → 密码推断矩阵**：

| 个人信息 | 典型密码模式 | 示例 |
|----------|-------------|------|
| 姓名拼音 | 姓名缩写+数字 | `zs1988` `ZhangSan` `zs888` |
| 生日 | 年月日组合 | `19880315` `880315` `3151988` |
| 手机号 | 后6位/后8位 | `885678` `13885678` |
| 身份证号 | 后6位 | `881234` |
| 配偶/子女生日 | 组合使用 | `20150618` |
| 车牌号 | 直接或倒序 | `辽A88888` |
| 宠物名 | 拼音/英文 | `xiaobai123` |
| 母校/公司名 | 缩写+年份 | `pku2006` `ali2020` |
| 常用数字 | 123456/888888/666666 | 常见弱密码 |
| Leet变形 | a→@/4, e→3, i→1, o→0, s→$/5 | `Zh@ngS@n` `P@ssw0rd` |

### 密码字典生成工具链

| 工具 | Stars | 核心能力 | 使用方式 |
|------|-------|----------|----------|
| **CUPP** | 4K+ | 交互式收集个人信息 → 自动生成个性化密码字典 | `python cupp.py -i` |
| **Crunch** | — | 基于字符集的密码生成器 | `crunch 6 12 -t zs@@@@ -o dict.txt` |
| **CeWL** | — | 从网站内容爬取关键词生成字典 | `cewl -d 2 -w dict.txt https://target.com` |
| **hashcat** | 21K+ | GPU加速密码破解（200+哈希类型） | `hashcat -m 0 -a 3 hash.txt ?l?l?l?d?d?d?d` |
| **John the Ripper** | 10K+ | 经典密码破解工具 | `john --wordlist=dict.txt hash.txt` |
| **Hydra** | 9K+ | 网络服务暴力破解 | `hydra -l user -P dict.txt ftp://target` |
| **RSMangler** | — | 基于单词的变异规则生成 | 输入"password" → Password1!/p@ssw0rd/password123等 |
| **Pipal** | — | 密码分析统计（分析泄露密码的模式） | 统计密码长度/字符分布/常见模式 |

### 撞库分析（Credential Stuffing Analysis）

> 撞库原理：用户在多个平台使用相同邮箱+密码组合。一旦某个平台的数据泄露，攻击者用泄露的账号密码去尝试其他平台。

| 分析维度 | 方法 | 工具/数据源 |
|----------|------|------------|
| 泄露关联 | 该邮箱/手机是否出现在已知泄露中 | DeHashed / SnusBase / Have I Been Pwned |
| 密码复用风险 | 泄露密码的复杂度判断复用概率 | Pipal 统计分析 |
| 密码模式识别 | 分析泄露密码推断该人的密码习惯 | 从泄露密码推断模式（如 `zs1988!` → 模式为 `姓名缩写+出生年份+特殊字符`） |
| 跨平台验证 | 同一邮箱在多个平台的注册情况 | Maigret / Blackbird |
| 密码Hash破解 | 获取到hash后离线破解 | hashcat / John the Ripper |

```

  → 出生日期: 1988-03-15
  → 手机号: 13812345678

  → 母校: 北京大学(PKU)

Step 2: 生成个性化密码字典（CUPP模式）
  → zs1988, zs880315, ZhangSan1988
  → 1385678, 885678
  → zs881234
  → pku1988, pku2015
  → zs20150618
  → zs888, zs666, zs123456
  → Zs@1988, Zh@ngS@n, ZS!1988 (Leet变形)
  → zhang1988!, zs19880315!! (加常见特殊字符)

Step 3: 泄露数据比对
  → DeHashed查 zhangsan@xxx.com → 发现2019年某网站泄露密码: zs1988!@#

  → 泄露密码复杂度: 11位含大小写+数字+特殊字符 → 中等复杂度（大概率复用于非重要平台）
  → 模式固定性: 始终使用 zs+日期+特殊字符 → 高复用风险
  → 建议: 该人在多个平台存在高概率密码复用
```

### 维度 2：数字身份发现（借鉴 Maigret/Blackbird/Sherlock）

> **核心思路**：一个人在不同平台可能使用相同或相似的用户名/邮箱/手机号。利用这一点，可以跨平台追踪一个人的完整数字足迹。

| 方法 | 工具/方式 | 覆盖范围 |
|------|----------|----------|
| **用户名跨平台搜索** | Maigret (3100+站点)、Blackbird (600+)、Sherlock (300+) | 全球社交媒体/论坛/电商/代码平台 |

| **用户名变体生成** | 自动生成常见变体（加数字/下划线/缩写） | 覆盖更多平台 |
| **昵称关联** | 同一昵称在不同平台的活跃度 | 微博/知乎/豆瓣/贴吧/小红书/抖音 |

### 泄露数据在身份确认中的应用

```
邮箱 → DeHashed/SnusBase → 
  发现关联信息: 用户名列表/姓名/电话/密码样式/IP/注册网站
  → 用户名 → Maigret/Sherlock → 社交媒体账号
  → 姓名 → 企查查/天眼查 → 工商信息
  → 电话 → PhoneInfoga/Truecaller → 归属地/关联
  → 密码样式 → 判断是否与其他平台相同密码（辅助确认同一人）
  → IP历史 → 地理位置验证
```

### 身份确认黄金法则

```
单一泄露源 → 仅标注[发现], 不做结论
2个独立泄露源 + 1个公开信息源 → 标注[高度疑似]
3个独立泄露源 + 2个公开信息源交叉一致 → [确认]
```

## 六、自动化调查工作流（借鉴 SpiderFoot 模块化思路）

```
Step 1：种子信息收集
  ├── 姓名 + 身份证号(部分)
  ├── 手机号（如有）
  ├── 邮箱（如有）
  ├── 企业名称
  └── 社交账号（如有）

Step 2：身份扩展（Maigret风格）
  ├── 用户名 → 3000+平台搜索 → 发现关联账号画像
  ├── 邮箱 → Holehe反向 → 发现注册平台列表
  ├── 手机号 → PhoneInfoga → 归属地/运营商/关联
  └── 头像 → PimEyes/Google Images → 跨平台头像匹配

Step 3：深度画像（Maltego风格）
  ├── 工商信息 → 全部任职企业 + 股东关系
  ├── 司法记录 → 裁判文书 + 执行 + 失信
  ├── 制裁扫描 → OpenSanctions/OFAC/UN
  ├── 社交分析 → 全平台内容+时间线+互动网络
  ├── 域名资产 → WHOIS+子域名+ICP+历史快照
  └── 资质核实 → 学历/资格证/执业注册

Step 4：关联扩展（六度关联）
  ├── 亲属 → 上市公司公告/裁判文书/工商股东
  ├── 密切商业伙伴 → 共同任职≥3家企业
  ├── 代持嫌疑 → 老人/无业/偏远地区股东
  ├── 一致行动人 → 同一时间买卖同一股票
  └── 资金关联 → 裁判文书中提及的往来方

Step 5：交叉验证
  ├── 企查查 vs 天眼查 vs 启信宝（三源验证）
  ├── 公开简历 vs 工商登记（履历真实性）
  ├── 社交媒体 vs 官方公告（言行一致性）
  └── 自述学历 vs 学信网（学历真伪）

Step 6：输出报告
  ├── 综合风险评估表（信号汇总）
  ├── 关联网络图谱（主要关联方/关联企业）
  ├── 时间线（关键事件/变更节点）
  └── 证据链附录（每项发现的来源）
```
