## 结论

- **WAF 求解已走通（纯 Python）**：阿里云 acw_sc__v2 透明 JS 挑战已逆向，
  cookie 计算 4 个独立 challenge 样本验证通过；带 cookie 复访**已通过

## 挑战机制

- 触发：部分出口 IP 请求 www.qcc.com 页面时返回 HTTP 200 + 挑战页
  （23670 字节，含 `acw_sc__v2` 标记与 `textarea#renderData`）。
- `arg1 = renderData.l1.slice(10,60)`：50 位 hex（头部固定 `5df5b`，
  疑似版本标记）。
- 浏览器行为：计算 cookie `acw_sc__v2=<值>`（1 小时有效期），setCookie
  后 reload（l2 缺失时直接 `document.location.reload()`）。
- 无验证码、无登录，纯 proof-of-work。

## 逆向过程

1. 混淆分析：`xXRQBR` IIFE 为 obfuscator.io 高强度预设——149 项字符串表
   + RC4 加密 + hash 旋转 + 自防御（`vr()` 校验 `xXRQBR.toString()` 完整性，
   篡改脚本会导致计算失败）。另有 `Math.random`/`Array.push`/`JSON.stringify`
   的运行时替换（反分析）。
2. 动态执行：在 Node vm 中运行**原始**挑战脚本（DOM stub：`window=globalThis`
   是关键，否则 `window['arg1']` 取不到值），捕获到 cookie。
3. 发现结构：cookie = 51 位确定性前缀 + 10 位随机 hex。
   - 确定性部分 = `'1234cf0d46-'`（11 位常量）+ 40 位 `permute(arg1[0:40])`。
   - 4 样本联合约束求解出唯一固定置换（模 `5df5b` 固定头的等价类）：
     `[7,34,35,21,0,16,4,26,11,30,15,3,32,38,31,39,5,10,14,13,2,12,8,17,18,22,9,23,33,24,36,25,20,6,28,27,1,37,19,29]`
   - 随机尾服务端无法预知，校验时忽略（实测任意随机尾均通过 WAF）。
4. 注意：公开渠道流传的旧置换表（如 `[15,35,29,24,...]` 50 元版）是
   **老版本 WAF** 的，对当前版本无效——必须以本次经验推导为准。

## robots.txt 边界

- `Disallow: /*?*`：所有带 query 的 URL 禁止 → 关键词搜索路径不用。
- 适配器仅支持 `/firm/{hex}.html` 干净 URL 直查（firm_id 可从搜索引擎
  索引的 firm 链接获得）。
